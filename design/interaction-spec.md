# 《百灵鸟在五线谱上飞行》交互与可用性规范 v1.0

> 交付物：交互状态机 · 信息架构 · 输入与触屏策略 · 判定反馈时序 · 容错与防挫败 · 难度曲线数值 · 可访问性 · 响应式规则 · 结算信息层级 · 新手流失点
> 视觉基线：`design/visual-spec.md` v1.0 + `design/tokens.css`（色值/字号/几何一律引用，不另起一套）
> 逻辑坐标系：1200 × 800（判定线 y=560，轨道 x=200/400/600/800/1000，音符生成 y=−50，noteSpeed 340 px/s）
> 本文档不写实现代码，但每个数值都给出可直接编码的口径。

## 0. 摘要：本文档要解决的 5 个真问题

| # | 问题 | 本规范的决定 | 章节 |
|---|---|---|---|
| 1 | 判定反馈会不会挡住玩家接下来要打的音符 | **反馈带 = 判定线上方 0~120px 的窄带 + 文字沿轨道向外偏移 + 同轨反馈独占替换 + 里程碑的"遮挡型"元素全部移到判定线下方** | §4 |
| 2 | 长按能不能刷分 | **keyup 才解锁 + 同轨最小重触发间隔 90ms + 空击不判 MISS + 每轨最多 1 个激活指针** | §3.1 |
| 3 | 玩家打错键会不会被惩罚 | **不惩罚**：空击只闪落点垫，不扣分、不清 combo、不产生判定音 | §5.1 |
| 4 | 最后 20% 会不会劝退 | **noteSpeed 全曲恒定（不改速度），难度只靠密度/chord/跨度提升；终章引入 chord 连线预告 + 落点垫预判高光 + 连续 MISS 反馈降级** | §6.3 |
| 5 | 手机能不能玩 | **移动端横屏 judgeY 560→620、spawnY −50→10（travel 不变）+ 判定线上方 40px 触控感应带 + 竖屏主动引导旋转** | §3.2、§8 |

**额外产出**：§11「对视觉规范的 9 条修改请求」——本规范在推导过程中发现视觉规范内部有 4 处会直接伤害可玩性的冲突，必须由视觉方确认或修订。

### 1.2 状态定义表

| 状态 | 进入条件 | 退出条件 | 期间可做的事 | 期间**禁止**的事 |
|---|---|---|---|---|
| **BOOT** | 页面加载 | ① 全部资源就绪　② 6s 超时（跳过 sprite 精细化，降级为纯色符头） | 无（可跳过：显示「加载较慢，继续」链接） | 任何按键无响应（避免误触被当成开始） |
| **TITLE** | BOOT 成功 / 从 RESULT 返回 / 从 PAUSED「返回标题」 | 按 空格 / 点击「开始」/ 点击「设置」 | Tab 浏览菜单、开关设置、查看最高分 | — |
| **COUNTDOWN** | 从 TITLE 按开始 / 从 RESULT「再来一次」 | ① 3.0s 计时到　② 教学阶段玩家按下正确键（提前进入） | 按键（教学阶段仅判定教学音符）、ESC 暂停 | 打分、计 MISS、计入 combo/统计 |
| **PLAYING** | COUNTDOWN 结束 / PAUSED「继续」 | ① t=180s 谱面结束　② ESC/P　③ 窗口失焦 | 按键/点击判定、ESC 暂停 | 改变难度/速度、缩放（浏览器缩放允许但不影响逻辑坐标） |
| **PAUSED** | ESC/P / 窗口失焦自动 / COUNTDOWN 中按 ESC | 「继续」/ ESC / 空格 / 点击暂停按钮 | 继续、重新开始（二次确认）、返回标题（二次确认） | 判定、计分（谱面时间轴冻结，音符静止） |
| **RESULT** | 谱面 t=180s 结束 | 「再来一次」/ R / 「返回标题」/ ESC | 读统计、按 R 重开、查看评价语 | — |

### 1.3 关键状态转换规则（工程师照抄）

```
T1  BOOT → TITLE      资源就绪 或 6s 超时
T2  TITLE → COUNTDOWN 触发源：keydown(Space) | click(#btn-start)
T3  COUNTDOWN → PLAYING  3.0s 计时到（GO 大字 250ms 后开始判定）
T4  PLAYING → PAUSED   触发源：keydown(Escape|KeyP) | click(#btn-pause) | window blur | visibilitychange(hidden)
T5  PAUSED → PLAYING   触发源：click(#btn-resume) | keydown(Escape|Space)
T6  PAUSED → TITLE     触发源：click(#btn-quit) 并通过二次确认
T7  PAUSED → COUNTDOWN 触发源：click(#btn-restart) 并通过二次确认
T8  PLAYING → RESULT   谱面时间轴到达 180.000s（最后一音过后 1.5s 触发结算动画）
T9  RESULT → COUNTDOWN 触发源：click(#btn-again) | keydown(KeyR)
T10 RESULT → TITLE     触发源：click(#btn-home) | keydown(Escape)
T11 任意 → PAUSED      window blur / visibilitychange(hidden)（仅 BOOT/TITLE 除外）
```

**必须遵守的时序细节**：

1. **窗口失焦自动暂停（T11）**：这是防挫败的第一道闸。切出去 3 秒回来看到满屏 MISS 是最致命的流失原因。
   - 触发后进入 PAUSED，面板标题改为「**已自动暂停**」，注脚改为「点击继续 · 回到游戏后按 空格」。
   - **不自动恢复**。玩家必须主动按「继续」，避免在没进入状态时突然被判一堆 MISS。
   - 恢复时给 **800ms 的「输入缓冲宽限」**：宽限期内按下的键不产生判定（避免回到瞬间的乱按被判 MISS）。宽限期内画面显示「准备…」小字（12px, text-lo, 居中 y=470）。
2. **暂停时谱面完全冻结**：音符停止下落、combo 冻结、进度条冻结、音乐挂起（`audioCtx.suspend()`）。恢复时音频与视觉必须**同步**（用 `audioCtx.currentTime` 的偏移量对齐，不要用 `setTimeout`）。
3. **结算进入时机**：谱面 t=180.000s 后，**再等 1.5s** 让最后一个音的特效播完，再滑入结算面板。玩家不会觉得"刚打完就弹窗"。
4. **PAUSED 面板在 COUNTDOWN 中也可进入**：此时「重新开始」等价于「取消教学回 TITLE」。

### 2.3 首次进入的 3 秒上手引导（COUNTDOWN）

**设计原则**：教学不是"文字说明"，而是**让玩家在 3 秒内亲手打出 3 个 PERFECT**。教程即示范。

**节拍脚本**（120 BPM，1 拍 = 500ms；教学音符速度 300 px/s，travel = 610/300 = **2.03s**）

| 时刻 | 大字（居中 x=600, y=380, 56/800） | 事件 | 音乐 |
|---|---|---|---|
| 0 ms | `READY` | 5 个键帽从左到右依次点亮（每 100ms 一个，共 500ms）；底部提示条 `跟着落下的光点，按下对应的键`（14/400 text-mid, y=670） | 底鼓 + 轻 shaker，无主旋律 |
| 500 ms | `3` | **教学音符 1**：轨道 2（空格，中心轨），从 y=−50 以 300px/s 落下，1.5s 后到判定线；同时该轨落点垫开始预判高光 | 同上 |
| 1500 ms | `2` | 教学音符 1 已判定（无论对错）→ **教学音符 2**：轨道 0（←） | 加入低音长音 |
| 2500 ms | `1` | 教学音符 2 已判定 → **教学音符 3**：轨道 4（→）；全部 5 键帽同时呼吸一次 | 贝斯进 |
| 3000 ms | `GO` | GO 大字 scale 1→0.85 + opacity 1→0（250ms）；教学层整体淡出 200ms；**主旋律第一音进入** | 主旋律 + 全奏 |

**教学判定的特殊规则（关键防挫败设计）**：

| 情形 | 处理 |
|---|---|
| 玩家在教学音符到达前按对了键 | 判定为 PERFECT，走**教学版特效**（12 芒星缩到 8 芒星尺寸 ×0.7，音效用真实 PERFECT 铃音但音量 −6dB）；额外一圈**青色教学环**（r 0→70，1px，300ms）表示"对了" |
| 玩家**没按** | 该教学音符到达判定线时自动判定为 **GOOD**（不是 MISS），显示「跟上下一次就好」小字 12px text-mid（1.0s 后淡出）。**不扣分、不清 combo、不进统计** |
| 玩家按错了键 | 按空击规则处理（§5.1）：落点垫闪一下，教学音符继续等待，直到超时判 GOOD |
| 玩家提前按对了所有 3 个 | **立即跳到 GO**（最短 1.2s），尊重熟练玩家 |

**重复进入**：第二次及以后跳过教学音符，直接 `3 · 2 · 1` 倒计时（**1.5s**，每 500ms 一个数字，大字 scale 1→1.15→1）+ 键位图示在 HUD 左下常驻（沿用视觉规范 §8.2）。
存储：`localStorage['bailingniao.seen_tutorial'] = '1'`。

**8 秒无操作自动演示**：进入 TITLE 后若 8 秒无任何输入，背景自动播放一段 6 秒的**自动演示**（AI 依次打出 3 连击 + 1 次 10 连击庆典的静音版本），吸引注意力。任意输入立即接管。

## 3. 键位与触屏的可用性细节

### 3.1 键盘：keydown / keyup 策略

**键位映射（用 `e.code`，不受输入法/键盘布局影响）**

| 轨道 | `e.code` | 备选 |
|---|---|---|
| 0 | `ArrowLeft` | `KeyA`（不启用，避免误触） |
| 1 | `ArrowUp` | `KeyW`（不启用） |
| 2 | `Space` | — |
| 3 | `ArrowDown` | `KeyS`（不启用） |
| 4 | `ArrowRight` | `KeyD`（不启用） |

**事件处理规则（逐条照抄）**

```
R1  判定表：ArrowLeft→0, ArrowUp→1, Space→2, ArrowDown→3, ArrowRight→4
R2  白名单之外的 key 一律不拦截（不 preventDefault，F5/F12/Ctrl+R 正常）
R3  仅当 e.ctrlKey / e.metaKey / e.altKey 全为 false 时才拦截方向键与空格的默认滚动
R4  所有被拦截的键必须 e.preventDefault()
R5  忽略 e.repeat === true 的事件（浏览器长按连发）
R6  每轨维护一个 held 布尔。keydown 时若 held[track] 已为 true → 忽略该事件（不产生任何判定）
R7  keyup 时置 held[track] = false（并熄灭该轨光柱）
R8  keydown 成功（通过 R6）后，置 held[track] = true
```

**为什么「必须 keyup 才能再触发」**：这是防止长按刷分的第一道闸，也是节奏游戏的标准手感（每个音一次完整按下—抬起）。代价是"同轨连打"需要快速抬指，但 160ms 的同轨最小间隔远大于人的抬指时间（~60–80ms），不构成障碍。

**第二道闸：同轨最小重触发间隔 `minRehitGap = 90ms`**

- 记录每轨 `lastJudgeTime`。若 `now − lastJudgeTime < 90ms` → **静默忽略**（无判定、无音效、无 combo 变化）。
- 注意：**若该轨当前窗口内仍有待判定音符，这次 keydown 应当正常判定那个音符**（90ms 只用于防止"同一瞬间刷两次"，不阻止正常的密集音符）。因此实现顺序是：
  1. 找到该轨「窗口内（|Δy| ≤ 65）且未判定」的音符，按最近的一个；
  2. 若找到 → 正常判定（PERFECT/GOOD）；
  3. 若没找到 → 视为**空击**（§5.1），且检查 90ms 闸门决定是否显示空击反馈。

**多轨道同时按住**

- **允许，且鼓励**（双押是核心爽点）。不做互斥。
- 但设**同时按下的轨道上限 = 4**：若已有 4 个轨道处于 held 状态，第 5 个 keydown 被静默忽略（不显示任何反馈）。
- 同一时刻最多 5 键的极端情况无实际意义，曲子里不会出现 5 押。

**关于「同时按下的时间差」**：两键按下时间差 ≤ **45ms** 视为同拍 chord（用于统计 chord 分布与判定吸附）。若两键相差 46–90ms 且分别落在 GOOD 窗口内 → 分别独立判定，各得各的分（不强制合并）。

**判定必须同步完成（性能硬要求）**

- **判定、计分、combo、状态更新全部在 `keydown` 事件的同步处理函数里完成**，不等 `requestAnimationFrame`。
- 视觉反馈在下一帧绘制（最大 1 帧 = 16.7ms 延迟）。
- **总延迟上限 1 帧**。理由：PERFECT 窗口只有 ±88ms，1 帧误差已占 19%；若输入延迟波动到 2–3 帧，玩家会感知为"随机"，这是节奏游戏最致命的体验问题。
- 禁止在输入处理里做 `setTimeout` 判定、禁止在输入处理里读 DOM 几何（避免强制同步布局）。

**输入延迟的显示反馈（可选但推荐）**：在设置抽屉里提供「判定偏移校准」滑块（−100ms ~ +100ms，步进 5ms），用于高延迟蓝牙键盘的用户。默认 0。

### 3.2 触摸 / 指针

**统一用 Pointer Events**（同时覆盖鼠标、触摸、手写笔），`touch-action: none` + `user-select: none` + `-webkit-tap-highlight-color: transparent` 全部加在 canvas 与舞台容器上。

**轨道归属规则**

1. 落点 `(x, y)` 换算到逻辑坐标（除以当前 `scale`）。
2. **命中判定带**：只有 `y ≤ judgeY + 20`（判定线及其上方 20px）才算一次判定输入。判定线以下的区域（HUD 区）不产生判定。
3. **轨道归属 = 离点击点 x 最近的轨道中心**。5 轨中点为 x = 300 / 500 / 700 / 900；x < 100 或 x > 1100 → 不归属任何轨道（点到了谱表外，忽略）。
4. **横向命中容差（解决"我明明看到它了"）**：
   - 音符符头半宽 23px。若点击点与音符中心的水平距离 **> 70 逻辑 px**（桌面鼠标）/ **> 90 逻辑 px**（触摸），则**不判定该音符**，但**仍然点亮对应轨道的落点垫**（表示"输入被识别，只是没打中"）。
   - 这条容差与纵向判定窗口（±65px）**同时满足**才判定。
   - 对比：纯纵向判定会让"稍微偏了一点"的点击直接 MISS，横向容差能挽救约 15–20% 的非主观失误。

**多点同时触摸**

| 场景 | 处理 |
|---|---|
| 两个手指按不同轨道 | 两个 `pointerId` 分别绑定两个轨道 → **原生支持双押**，两个轨道各自产生判定与特效 |
| 三个手指按三个轨道 | 同上，支持三押（曲子最高 chord = 3） |
| 两个手指按**同一轨道** | **第一个 pointer 绑定该轨；第二个 pointer 不再产生判定**，但可以点亮同一轨的落点垫（不重复计分） |
| 手指滑出画布 | 用 `setPointerCapture(e.pointerId)` 捕获，`pointerup/pointercancel` 时释放；`pointercancel`（系统手势打断）也必须释放该轨的 held 状态 |
| 手指按住不动 | 持续显示该轨光柱（visual 反馈），但**不重复判定**（同 R6） |

**防误触清单**

| 风险 | 对策 |
|---|---|
| 点到 HUD 按钮（暂停/设置）时同时触发判定 | HUD 层 `z-index` 高于画布且按钮 `pointer-events: auto`，命中按钮的指针不进入判定逻辑（事件在 HUD 层被 `stopPropagation`） |
| 底部系统手势条（iOS）误触 | 判定输入区 y ≤ judgeY+20；HUD（暂停按钮）位于判定区外；HUD 底部加 `padding-bottom: env(safe-area-inset-bottom)` |
| 双击缩放 / 长按选中 / 长按弹出菜单 | `touch-action: none`、`user-select: none`、`-webkit-touch-callout: none`、`contextmenu` 在舞台内 `preventDefault` |
| 误触导致空击 | 空击无惩罚（§5.1） |
| 一次触摸被识别成多次（浏览器 ghost click） | 只监听 `pointerdown`，**不监听 `click`**；指针抬起后 250ms 内同一轨不再接受新 pointer（防抖） |

**移动端判定线位置（关键）**

- 拇指自然落点在屏幕下方 60%–85% 区域；判定线若在 70% 高度，会被拇指指腹遮挡。
- 移动端横屏时把 `judgeY` 从 **560 → 620**，同时把 `spawnY` 从 **−50 → 10**，**保证 travel = 610 逻辑 px 恒定不变**（难度曲线不受影响）。
- 判定线以下的布局整体下移 +60：`Combo 标签 576→636`、`Combo 数字 596→656`、唱名行 `586→646`；键位图例（左下）与暂停按钮（右下）**在移动端隐藏**（改用画面上的触控提示）。
- **触控感应带**：判定线上方 40 逻辑 px（y ∈ [580, 620]）内点击也算命中（"手指粗"容差）。
- **触控提示带**：移动端在判定线上方 120 逻辑 px（y=500）处画一条 `rgba(255,196,77,.05)` 的 40px 高横带，提示"手指落在这里"；仅在 `pointer: coarse` 显示。

### 3.3 视口、横竖屏与安全区

**viewport 声明**

```
<meta name="viewport"
      content="width=device-width, initial-scale=1, viewport-fit=cover">
```

- **不写 `user-scalable=no`**（会违反 WCAG 1.4.4 缩放要求）。
- 舞台内滚动用 `touch-action: none` 解决，与页面级缩放不冲突。
- `viewport-fit=cover` 启用安全区。

**安全区**

| 位置 | 用途 | 处理 |
|---|---|---|
| `env(safe-area-inset-bottom)` | 移动端底部 HUD | HUD 容器 `padding-bottom: max(env(safe-area-inset-bottom), 8px)` |
| `env(safe-area-inset-left/right)` | 横屏刘海 | 舞台水平居中偏移 `calc((100vw - env(safe-area-inset-left) - env(safe-area-inset-right)) / 2)` |
| `env(safe-area-inset-top)` | 顶部 HUD | 顶栏 `padding-top: max(env(safe-area-inset-top), 4px)` |

**横竖屏策略**

| 状态 | 处理 |
|---|---|
| 横屏（`orientation: landscape`） | 正常游玩。移动端额外启用 `judgeY = 620` |
| 竖屏（`orientation: portrait` 且 `pointer: coarse`） | **不直接缩放硬塞**。显示全屏「请旋转设备」层：居中一个 120×200 的旋转手机 SVG（2s 循环 rotate 90°）+ 文字「横屏游玩体验更佳」+ 一个 12px 次要链接「仍要竖屏游玩」 |
| 用户强制竖屏 | 进入**竖屏降级模式**：scale = `min(w/1200, h/800)`，判定线仍在 560 → 屏幕上位于约 30% 高度，下方大片空白 → **把舞台垂直居中偏上（top: 12%），下方空白区填入"设置/最高分/操作说明"的 DOM 卡片**（可滚动），并把触控热区扩大为"判定线上下 200 逻辑 px 内的全宽横向映射"。**明确标注：竖屏为降级体验，不保证可玩性** |

**音频解锁**

- 浏览器要求用户手势后才能播放音频。`TITLE → COUNTDOWN` 的那次空格/点击事件内必须 `audioCtx.resume()`。
- 若 1 秒后 `audioCtx.state !== 'running'`，在 HUD 右上角显示一个「🔇 点击开启声音」小徽章（48×48 触达区），点击后 `resume()` 并移除徽章。
- 结算界面的按钮点击同样可作为解锁手势（作为二次保险）。

## 4. 判定反馈的时序与可读性

### 4.1 核心原则：特效不挡下一个音符

**推导**（标准模式，noteSpeed 340 px/s）

- 音符从 y=−50 生成 → y=560 判定，行程 610px，**travel = 1.795s**。
- 玩家在 t=0 击中一个音后，若同轨下一个音间隔 1/2 拍（250ms），它在 t=0 时位于 y = −50 − 340×0.25 = **−135**（屏外）。
- 它到达反馈带（y ∈ [440, 560]）的时刻 = (440 + 135)/340 = **1.69s** 之后。
- 反馈文字寿命 ≤ **360ms** ⟹ **垂直方向天然不冲突**（差 4.7 倍）。

**所以真正的遮挡风险只有三处**，规范逐条解决：

| 风险 | 现象 | 解决方案 |
|---|---|---|
| **R1 同轨反馈叠加** | 密集打同轨时，前一个爆闪/涟漪与后一个到线的音符叠在一起 | **每轨反馈独占**：新判定发生时，立即把该轨道上一个未完成的特效（爆闪/涟漪/文字/飘字）用 60ms 淡出并从池中移除，同一轨道永远只有 1 个反馈实例 |
| **R2 里程碑遮挡型元素** | 横幅/徽章/鸟剪影横跨下落通道 | **全部迁到判定线下方**（见 §4.4） |
| **R3 反馈文字与本轨音符共线** | 文字画在轨道中心，遮住正在落的音 | **文字沿轨道向外偏移**（见 §4.2） |

### 4.2 反馈文字的位置：外扩偏移表

**规则：反馈文字中心 x = 轨道中心 + 该轨外扩偏移；y 基准见表。**

| 轨道 | 中心 x | 外扩偏移 | **文字中心 x** | y 基准（PERFECT/GOOD/MISS） | 尺寸 |
|---|---|---|---|---|---|
| 0 | 200 | −46 | **154** | 470 / 482 / 492 | 22 / 18 / 18 |
| 1 | 400 | −40 | **360** | 470 / 482 / 492 | 同上 |
| 2 | 600 | 0（**改为上移**） | **600** | **430** / 442 / 452 | 同上 |
| 3 | 800 | +40 | **840** | 470 / 482 / 492 | 同上 |
| 4 | 1000 | +46 | **1046** | 470 / 482 / 492 | 同上 |

**校验**

- 相邻文字中心间距 = 206 / 240 / 240 / 206 px；最宽文字（PERFECT，22/800，约 92px 宽）半宽 46px → **相邻文字边缘最小间距 114px**，绝不重叠。✓
- 外扩后与本轨符头中心（半宽 23px）的距离：轨道0 → 46px > 23 ✓；轨道1 → 40px > 23 ✓；轨道3/4 同理 ✓。**不与本轨音符共线。**
- 轨道 2 无法外扩（两侧是轨道 1、3），故改为**上移到 y=430**（判定线上方 130px）。下一同轨音到达 y=430 的时刻 ≥ 1.9s，文字寿命 360ms，安全 ✓。
- 轨道 0 的文字中心 x=154，与谱表左边界 x=140 相距 14px，在谱表内 ✓。轨道 4 的 x=1046 与右边界 1060 相距 14px ✓。

**其他可读性规则**

- 反馈文字一律 `skewX(-6deg)`（视觉规范已有）。
- PERFECT：22/800 `#FFF4C8` + 2px 白描边（`-webkit-text-stroke: 2px rgba(255,255,255,.55)`）+ `text-shadow: 0 2px 6px rgba(0,0,0,.75)`。
- GOOD：18/600 `#4FD1E8` + 深色投影，无描边。
- MISS：18/600 `#FF4D6D` + 深色投影，无描边。
- **颜色之外的第二编码**：PERFECT = 12 芒星；GOOD = 8 芒星；MISS = 无爆闪（音符碎裂）。**形状差异必须保留**（色弱玩家靠形状区分）。
- `+分数` 飘字：14/700 tabular，位于判定文字下方 20px，轨道色（视觉规范 §8.3 的 22px 改为 20px 以保证不越出反馈带）。

## 5. 容错与防挫败设计

### 5.1 打错键（空击）

**决定：允许，且完全无惩罚。**

| 维度 | 规则 |
|---|---|
| 是否允许 | **允许**。阻止空击会破坏"敢按"的心态，反而让玩家变保守 |
| 是否扣分 | **否** |
| 是否清 combo | **否** |
| 是否算 MISS | **否**。MISS 只在"该有音符而没打"时产生 |
| 视觉反馈 | 该轨**落点垫闪一次**（轨道色 60% → 0，180ms）+ 落点处一圈 8px 微涟漪（可省略）。**不产生判定文字、不爆闪、不产生粒子** |
| 听觉反馈 | 打一个**极轻的"拨片"音**（200Hz 短噪声，30ms，音量 **−24dB**，与任何判定音完全不同频段）→ 让玩家知道"输入被识别了，但没打中" |
| 频率保护 | 同一轨道 400ms 内空击 ≥3 次 → 额外在该轨落点垫下方显示一个**向下的箭头提示**（12px SVG，600ms 后淡出），不出现任何文字说教 |
| 上限 | 全局每帧最多渲染 3 个空击反馈，避免密集乱按时闪成一片 |

**为什么这样设计**：节奏游戏的"空击"通常是玩家节奏错位或过度自信的表现。如果空击有惩罚，玩家会学会"不敢按"，准确率会下降而难度体感上升；空击无惩罚，则"多按几下"是安全的，玩家会更敢抢拍，爽感更高。

### 5.2 MISS 的可读性与"看起来像崩了"的三个来源

| 来源 | 表现 | 对策 |
|---|---|---|
| **高频警报感** | 连续 MISS 时满屏玫红闪烁 | 连续 MISS 降级（§4.3）：第 3 次起不闪红、文字 opacity .65、碎屑 3 片 |
| **"归零 = 失败"** | Combo 数字变红 / 大幅震动 | Combo 归零**不染红**（红色是 MISS 专用色，混用会误读），改为**下沉 8px + 降饱和 200ms**；**不震屏**（震屏只给里程碑） |
| **"音符卡住了"** | MISS 后音符继续下落，看起来像没被处理 | MISS 的音符**在越过 y=590 时立即碎裂消失**；被击中的音符 90ms 内吸附消失 |

**其他 MISS 规则**

- 同一轨道 **400ms 内不重复显示 MISS 文字**（第二次只闪判定线段，文字不叠加）。
- MISS **不弹浮窗、不暂停、不中断音乐**。
- MISS 音与其他音效区分：MISS 用**低频下滑**（200→80Hz，180ms），与 PERFECT 的高频铃音、GOOD 的单音在音高与频谱上完全分离。

### 5.4 练习模式 / 判定辅助 / 速度调节

**练习模式（提供，作为可选项，默认关闭）**

| 维度 | 标准 | 练习 |
|---|---|---|
| noteSpeed | 340 px/s（beatGap 340px） | **290 px/s**（beatGap 290px），travel 610/290 = **2.10s** |
| 判定窗口 | ±30 / ±65 px | 同（**不放松判定窗口**，避免形成错误习惯） |
| GOOD 窗口虚线 | 默认关 | **常亮** |
| 落点垫预判高光 | 开 | 开（强度更高：判定前 0.5s 起亮） |
| 前 15 秒 | 正常计分 | **不计分、不判 MISS**（热身区） |
| 80–100% 终章 | 完整终章 | **替换为简化版**（音符数 125 → 78，密度 1.74 → 1.08 notes/beat，chord ≤2） |
| 结算 | 完整结算面板 | **不进结算面板**，直接回 TITLE 并显示「热身完成 · 已记录 12 连击」小卡 |
| 徽章/庆典 | 全部 | 保留（10 连击庆典保留，这是爽感来源） |

**判定辅助**

| 辅助 | 默认 | 说明 |
|---|---|---|
| PERFECT 窗口虚线（y=530/590） | **开** | 视觉规范已定义，保留 |
| GOOD 窗口虚线（y=495/625） | 关（练习模式开） | 设置里可单独开 |
| **落点垫预判高光**（新增） | **开** | 音符进入 y ∈ [430, 530]（判定前 90–380ms）时，该轨落点垫 opacity 0.35→0.70 + 加 2px 同色描边。**低成本高收益的可读性提升** |
| **chord 连线预告**（新增） | **开** | 终章的 chord 音符，在判定前 **400ms** 时，在两条轨道的落点垫之间画一条 1px `rgba(255,196,77,.18)` 的弧线，判定时淡出。这是解决"双押劝退"的核心手段 |
| **轨道序号**（新增） | **开** | 判定线下方的唱名行改为 `1 do` / `2 re` / `3 mi` / `4 fa` / `5 sol` |
| 判定线偏移校准 | 关 | 设置里 −100ms ~ +100ms，步进 5ms |

**速度调节：游戏中不可调**

- **不允许在游戏进行中调节速度**。理由：① 实时变速会让"音符 ↔ 音乐"的对应关系在玩家脑中断裂，产生"我明明卡住了"的挫败；② 玩家会无脑调到最慢 → 爽感归零、难度归零。
- 速度**只能在开局前选择**（标准 340 / 练习 290），且**整局恒定**。
- 由于节拍线间距与 noteSpeed 绑定（视觉规范 §4.2），两种模式的 beatGap 分别为 340px / 290px，**一首曲子的时间轴在两种模式下是同一份**（只是空间密度不同）。

### 5.5 其它防挫败规则

| 规则 | 说明 |
|---|---|
| **前 8 秒不计分** | 开局前 8 秒的判定不计入分数/统计（音符照常落下、照常有反馈），让玩家"先上手再算分" |
| **前 15 秒保护期** | 前 15 秒内 MISS **不清 combo**，只断显示。15s 之后恢复正常 |
| **不出现 Game Over** | 节奏游戏没有失败态。任何情况下都能打到最后 |
| **结算必有正向引导** | C/D 档也必须给出"下一步建议"（见 §9.3） |
| **无倒计时惩罚** | 谱面结束前 10 秒不做任何"即将结束"的警告闪烁，只让进度条填充色转 `--lane-1`（视觉规范已有） |

| # | 做法 | 具体参数 |
|---|---|---|
| **1** | **双押只占小部分** | 终章双押 ≤ 25% 音符，三押 ≤ 12%；**连续三押不超过 2 次** |
| **2** | **chord 连线预告** | 终章所有同拍多键音符，在判定前 **400ms** 于相关轨道的落点垫之间画 1px `rgba(255,196,77,.18)` 弧线；玩家能"提前知道要一起按" |
| **3** | **落点垫预判高光** | 判定前 90–380ms，落点垫 opacity 0.35→0.70 + 2px 描边（**不覆盖音符本身**） |
| **4** | **密度渐进而非断崖** | 任意连续 2 小节内，notes/beat 的增量 ≤ **1.0**；禁止"空 4 小节然后 8 连打" |
| **5** | **同轨留白** | 终章内 \|Δlane\| = 0 的连续 ≤ 2 次；每 4 小节至少有 1 个 \|Δlane\| ≥ 2 的"移动音"来换手 |
| **6** | **MISS 反馈降级** | 连续 MISS ≥3 起，判定线不闪红、文字降透明度（§4.3）—— 终章是压力最大处，反馈必须"轻" |

| **8** | **收尾给掌控感** | 最后 2 小节密度降到 1.0 notes/beat，只保留 1/2 与 1/4 拍；最后 4 小节的华彩只有一个 3 押；最后 1 个音后留 **1.5s 静默**再进结算，让"余韵"落地 |

## 7. 可访问性（a11y）

### 7.1 色觉差异下的 5 轨区分（不能只靠颜色）

**问题诊断**（视觉规范 §2.4 的色板在灰度/色盲模拟下）

| 轨道 | HEX | 相对亮度 L* | 灰度近似 | 问题 |
|---|---|---|---|---|
| 0 ← | `#FFD166` | 79 | ~186 | — |
| 1 ↑ | `#FF8A5C` | 65 | ~146 | 与轨道4 灰度接近 |
| 2 空格 | `#F4F7FB` | 96 | ~245 | — |
| 3 ↓ | `#63D9A6` | 78 | ~180 | **与轨道0 灰度几乎相同**（186 vs 180） |
| 4 → | `#7FA8F0` | 67 | ~152 | 与轨道1 灰度接近 |

→ **纯色标在灰度下无法区分轨道 0/3 与 1/4**。

**解决方案（主方案，不依赖色板）—— 三重冗余编码**

| 编码 | 实现 | 说明 |
|---|---|---|
| **① 位置编码（最强）** | 5 个固定 X 位置 | 玩家主要靠"从哪条线下来"识别，位置本身是最强编码 |
| **② 序号 + 唱名** | 判定线下方唱名行改为 `1 do` / `2 re` / `3 mi` / `4 fa` / `5 sol`（11px serif `--text-lo`） | **零成本**，位置与轨道中心严格对齐 |
| **③ 键位图例常驻** | 左下角 5 个键帽，每个键帽**上方角标**标 1–5（11/700 tabular） | 玩家随时能把"我按的键"对应到"哪条线" |
| **④ 落点垫尺寸分级** | 宽度 88 / 92 / **104** / 92 / 88，高 10 / 11 / **12** / 11 / 10 | 中心轨最宽最大，形成视觉主角；灰度下也有 10% 级差异 |

**可选方案：色弱友好模式**（设置抽屉内的开关，默认关）

- 打开后 5 轨换成**经校验的替代色板**，要求：① 相邻轨 ΔE ≥ 15（deuteranopia/protanopia 模拟）；② 亮度形成**单调阶梯**（灰度下可区分）；③ 判定色不变。
- 需要视觉方用色觉仿真工具校验后给定 HEX，本文档不擅自改动已确认的色板。
- **该模式同时自动打开**：GOOD 窗口虚线 + 落点垫预判高光 + 轨道序号（因为色弱玩家同时也是需要更多辅助的人）。

**不依赖颜色的判定区分**：PERFECT = 12 芒星 / GOOD = 8 芒星 / MISS = 无爆闪+碎裂。**形状差异是判定区分的最终保障，不可为了美观而削弱。**

### 7.2 键盘可导航的菜单

| 要求 | 实现 |
|---|---|
| 所有交互元素是原生控件 | 开始/暂停/结算/设置全部用 `<button>` / `<input type="radio">` / `<input type="checkbox">` / `<select>`，**不使用 div 模拟按钮**（视觉规范 §10 反例 20–21） |
| 焦点顺序 | 与视觉顺序一致：标题页 = [开始] → [模式: 标准/练习] → [设置] → [最高分链接?]；设置抽屉 = [色弱友好] [GOOD 窗口线] [预判高光] [减弱动效] [判定偏移滑块] [关闭] |
| 焦点环 | `outline: 2px solid var(--milestone-gold); outline-offset: 3px;` — 与深底对比度远超 3:1 ✓ |
| 焦点可见性 | 移除 `outline: none`，禁止只靠 `:focus-visible` 的 `box-shadow` 代替轮廓 |
| 对话框焦点管理 | 打开时 `focus()` 主按钮；关闭时把焦点还给触发元素；`Tab` 循环限制在对话框内（焦点陷阱） |
| 快捷键标注 | 面板上用 `<kbd>` 标注（Esc / Space / R / P），并加 `aria-keyshortcuts` |
| 开始界面 | `keydown(Space)` 在任何界面都触发「开始」；`Esc` 在 TITLE 无操作（不弹窗） |
| 游戏中 | 游戏内 Tab 无意义，但 Esc 随时可达暂停面板；**暂停面板的每个按钮都可用键盘到达** |

### 7.3 `prefers-reduced-motion` 降级方案

**检测**：`window.matchMedia('(prefers-reduced-motion: reduce)')`，并提供游戏内「减弱动效」开关（三态：跟随系统 / 开启 / 关闭），存 `localStorage`。

| 元素 | 标准 | 减弱动效 |
|---|---|---|
| 屏震（里程碑） | A0 = 4/7/9/12px，26Hz | **A0 = 0**（完全关闭） |
| 全屏白闪（100 COMBO） | opacity 0→.85→0，260ms | 改为**边框内发光** `inset 0 0 80px rgba(255,248,231,.30)`，260ms，无全屏亮度跳变 |
| 粒子数量 | 8 / 4 / 7 / 120 片 | **× 0.35**（8→3、4→2、7→3、120→42） |
| 背景星尘呼吸 | 4–8s 循环 | **停止**（保留静态星点） |
| 纸纹颗粒 | overlay .035 | **保留**（静态，不动） |
| 百灵鸟漂浮 / 掠影 | 6s 浮动 + 每 9s 掠影 | 漂浮**停止**（保留静态剪影）；掠影**保留但透明度 .22→.12** |
| 里程碑的位移/缩放 | scale .6→1 / translateY | 改为**纯淡入淡出 ≤ 150ms** |
| 判定文字上浮 | 上浮 24px | 改为**原地淡出**（保留位置与时长，不上浮） |
| 判定线白闪 | 60ms 白闪 | **保留**（这是信息，不是装饰） |
| 音符吸附回弹 | scaleY .8→1，90ms | 改为**直接淡出 90ms**（去掉回弹） |
| Combo / 分数数字回弹 | scale 1→1.12→1 | 改为**颜色/透明度变化**（数字本身仍变化，属信息） |
| 背景渐变流动 | 静态 | 静态 |
| 进度条 | 线性填充 | 线性填充（信息） |

**铁律**：**游戏本体运动（音符下落、谱线滚动）永不关闭**。减弱动效只影响装饰性运动。
**注意**：判定文字上浮属于"装饰"还是"信息"？→ 判定文字的位置变化会被玩家用来判断节奏，属边缘情况；本规范选择**保留上浮但缩短到 12px**，以维持空间连续性，同时降低运动量。

### 7.5 字号放大与文本缩放

| 要求 | 规则 |
|---|---|
| 浏览器页面缩放（Ctrl +） | **必须支持**。viewport 不写 `user-scalable=no` |
| 浏览器「仅放大文本」 | Canvas 内文字不受影响（自行绘制）；DOM 覆盖层需用 `rem` 单位 |
| **画布与 DOM 的缩放同步** | 覆盖层与舞台放在同一 1200×800 容器内，一起 `transform: scale(fitScale)`，**保证文字与画布不错位** |
| **最小可读字号** | DOM 覆盖层文字**不跟随 scale 无下限缩小**：规则 `domScale = max(fitScale, 0.78)`，画布仍用 `fitScale`。于是窄屏下画布变小但文字保持可读（可能溢出面板 → 面板改为可滚动/重排） |
| **窄屏精简模式**（fitScale < 0.72 时） | HUD 隐藏次要元素，保留全部数值：隐藏「曲名」「规则注脚」「键位图例标签」「唱名」，保留 SCORE 数值、COMBO 数值、进度条、准确率、评级徽章（缩到 40px） |
| 覆盖层自适应 | 面板宽度用 `min(720px, 92vw)`、高度 `max-content` + `max-height: 88vh; overflow-y: auto` |
| 舞台缩放 > 1.5× | 画布 `fitScale` 继续放大（逻辑坐标不变），DOM 覆盖层保持 1×（不跟随放大），保证文字不被放大到荒谬 |
| 关键文字最小实际高度 | 任何关键文字的实际渲染高度 ≥ **11px**；次要 ≥ 9px（视觉规范 §3.2 的 11px 基础在 0.72 缩放下会变成 7.9px，必须由 `domScale` 下限兜住） |

## 8. 响应式与窗口尺寸

### 8.1 缩放模型

- 逻辑坐标恒为 1200×800，所有内容用 `transform: scale()` 等比适配。
- **桌面/平板**：`fitScale = min(vw / 1200, vh / 800)`（contain，不裁切）。
- **触屏横屏**：`fitScale = min(vw / 1200, vh / 800)`，另外 `judgeY = 620`、`spawnY = 10`。
- **canvas 的 DPR 处理**：`canvas.width = 1200 * dpr`，CSS 尺寸 1200×800，`ctx.setTransform(dpr,0,0,dpr,0,0)`，dpr 上限 2（视觉规范 §9.3）。

### 8.2 各类窗口的处理（推荐：保持比例缩放 + 背景延展，不重排谱面）

| 窗口 | 比例 | fitScale | 表现 | 处理 |
|---|---|---|---|---|
| **16:10（1200×750~800）** | 1.5 | 1.00 | 满屏 | 标准布局 |
| **16:9（1920×1080）** | 1.78 | 0.9375 | 上下留 96px | 背景渐变延展填满上下（见下） |
| **21:9 极宽（2560×1080）** | 2.37 | 0.9375 | 左右留 660px | **左侧/右侧放"延伸的谱表"**：L0 背景层的水平渐变与星尘铺满全屏，谱线与谱表边界仍限制在 1200 内 → 画面不显得"贴中间的一块" |
| **4:3（1024×768）** | 1.33 | 0.853 | 上下留 85px | 背景延展 |
| **超宽但矮（3440×720）** | 4.78 | 0.90 | 左右留 920px | 同 21:9；**同时进入"窄屏精简模式"?** 否——精简模式按 fitScale 判定，0.90 不触发 |
| **超窄（390×844 手机竖屏）** | 0.46 | 0.325 | 舞台 390×260，上下大量空白 | **主动引导旋转**（§3.3）；强制竖屏则进入竖屏降级模式 |
| **平板竖屏（768×1024）** | 0.75 | 0.64 | 舞台 768×512 | 触发**窄屏精简模式**（fitScale 0.64 < 0.72）；`pointer: coarse` → 也提示旋转 |
| **平板横屏（1024×768）** | 1.33 | 0.853 | — | 若 `pointer: coarse` → 移动端 judgeY=620 |
| **窗口小于 1200×800（800×600）** | 1.33 | 0.667 | 舞台 800×533 | 精简模式（0.667 < 0.72）；文字保底缩放 0.78 |

**关键原则**

| 原则 | 说明 |
|---|---|
| **不重排谱面** | 音符的 X 坐标是"五线谱竖置"隐喻的载体（5 条垂直谱线），重排会摧毁核心概念。**任何窗口尺寸下都保持 1200×800 逻辑布局 + 等比缩放。** |
| **不裁切** | 永远 contain，不 cover（裁切会切掉两侧轨道） |
| **背景延展，消灭黑边** | `body` 使用与 `.stage` 相同的天空渐变（`background-attachment: fixed` + `background-size: cover`），使 letterbox 不可见。**绝不允许出现纯黑条**（视觉规范 §10 反例 18–19） |
| **letterbox 下的额外装饰** | 左右留白区可放**极淡**（opacity ≤ .06）的延伸谱线与星尘，暗示"总谱比视野更宽" |

### 9.2 评级依据（明确定义，结算页要用小字说明）

**准确率 acc = (PERFECT × 1.0 + GOOD × 0.5) ÷ (PERFECT + GOOD + MISS)**

| 评级 | 条件 | 附加条件 |
|---|---|---|
| **S** | acc ≥ **95%** | 且 最大连击 ≥ **50**；且 MISS ≤ 总音符数 × 5% |
| **A** | **88%** ≤ acc < 95% | — |
| **B** | **75%** ≤ acc < 88% | — |
| **C** | **60%** ≤ acc < 75% | — |
| **D** | acc < 60% | — |
| **PERFECT 徽章** | 全部 PERFECT 且 MISS = 0 | 与字母评级并行显示（缎带优先于 NEW RECORD） |

> 注：评级的「连击条件」只用 **S** 一档（其他档不设连击门槛），避免玩家因一次断连就被"降级"而挫败。

| **2** | **不知道什么时候按**（0–15s） | 乱按一通后退出 | 缺乏判定参照 | ① 3 秒教学（3 个教学音符，错了判 GOOD 不判 MISS）；② PERFECT 窗口虚线**常亮**；③ 落点垫预判高光；④ 前 8 秒不计分 | 教学结束时的 PERFECT 率 > 50% |
| **3** | **跟不上速度**（10–30s） | combo 频繁断裂 | 音符间隔过密 | ① 前 12 秒（#1 段）同轨间隔 ≥ 500ms；② 前 8 秒不计分 + 前 15 秒不清 combo；③ 落点垫预判高光（判定前 380ms 就有信息） | 首次会话 30s 内的 MISS 率 < 35% |
| **4** | **打错键被惩罚** | 变得不敢按 | 空击若被判 MISS，玩家会变保守 | **空击零惩罚**（不扣分、不清 combo、不判 MISS），只闪落点垫 + −24dB 拨片音 | 空击率高的玩家，其后 60 秒的准确率不低于其他玩家 |
| **5** | **第一次 MISS 的挫败**（30–90s） | 看到 combo 归零变红，退出 | 红色=失败的心理暗示 + 归零的冲击 | ① Combo 归零**不染红**（下沉 + 降饱和）；② 连续 MISS ≥3 起**反馈降级**（不闪红）；③ 连续 MISS 达 5 次 → 显示「放慢一点也没关系」+ 8 秒保护期（判定放宽 20%） | MISS 后 30 秒内退出率 < 8% |
| **6** | **看不清是哪个轨道** | 频繁空打 → 退出 | 纯色编码在色弱/小屏下失效 | ① 唱名行加序号 `1 do`…`5 sol`；② 键位图例常驻并带 1–5 角标；③ 落点垫尺寸分级；④ 可选色弱友好模式 | — |
| **7** | **手指遮挡判定线**（移动端） | 看不到判定线 → 乱按 → 退出 | 判定线在屏幕 70% 高度，正好在拇指区 | 移动端 `judgeY = 620` + `spawnY = 10`（travel 不变）+ 判定线上方 40px 触控感应带 + 触控提示带 | 移动端 MISS 率 / 桌面 MISS 率 ≤ 1.4 |
| **8** | **误按 ESC/P 中断** | 被暂停后不知怎么回去，退出 | 暂停面板不可见/不明确 | ① 暂停成本低（面板只有 3 个按钮 + 快捷键注脚）；② 「重新开始」「返回标题」二次确认 3s 倒计时；③ 失焦自动暂停且**不自动恢复**（避免回来被误判） | 暂停后 15 秒内恢复率 > 85% |
| **9** | **没有声音** | 以为游戏坏了，退出 | 浏览器自动播放策略 | ① 开始按钮点击时 `audioCtx.resume()`；② 1 秒后仍非 running → HUD 显示「🔇 点击开启声音」徽章；③ 结算页按钮作为二次解锁手势 | 音频解锁成功率 > 95% |
| **10** | **卡顿**（低端机） | 感觉"游戏崩了"，退出 | 帧率不足 | ① 自动降级：3 秒平均 fps < 40 → 粒子 ×0.5、关闭纸纹与 backdrop-filter、屏震幅度 ×0.5；② 降级时提示一次「已为你降低特效以保持流畅」；③ 音符 sprite 预渲染 | 低端机 fps ≥ 40 |
| **11** | **不知道分数怎么算** | 觉得"打得好分数却低" | 公式不透明 | 开始页规则注脚 + 结算页注脚说明平均分公式 + 得分飘字（`+120`）显示每次命中加了多少 | — |
| **12** | **结束太突然** | 最后一秒还在紧张，弹窗打断 | 无收尾 | 最后 8% 密度回落 + 最后 1.5s 静默 + 结算面板滑入前无遮挡 + 100 连击有专属庆典 | — |
| **13** | **想再玩找不到入口** | 退出 | 入口不明确 | 「再来一次」是结算页主按钮且**默认获得焦点**；`R` 键立即重开；标题页显示最高分 | 单局后立即重开率 > 55% |
| **14** | **难度突然跳变** | 在某处崩溃 | 段与段之间断层 | 任意连续 2 小节 notes/beat 增量 ≤ 1.0；每段开始前 2 小节有一次"密度预告"（第 4 段起，进段前 2 小节加一次全轨落点垫闪烁作为视觉信号） | — |

### 10.2 新手体验时间线（产品视角）

```
0s ──── 3s ──────── 15s ────────────── 45s ──────────── 180s
 │      │            │                   │                │
 进入   教学结束     保护期结束          心流开始           结算
 │      │            │                   │                │
 标题   首个真音     正常计分            密度提升         评级+评价语
 8s无操作→自动演示   前15s不清combo      保护期可用一次
```

**每个阶段的"一句话设计目标"**

| 阶段 | 目标 | 关键手段 |
|---|---|---|
| 0–3s | 知道要做什么、愿意按 | 呼吸提示 + 自动演示 |
| 3–15s | 打出 3 个 PERFECT，建立信心 | 教学 + 不计分 + 预判高光 |
| 15–45s | 稳定跟住，形成节奏感 | 密度 0.5→1.0 notes/beat |
| 45–180s | 有挑战但不被击溃 | chord 连线预告 + MISS 反馈降级 + 保护期 |

> 本节列出本规范推导过程中发现的、会直接影响可玩性的冲突。前 4 条是**必须修订**（会伤害核心体验），后 5 条是**建议微调**。

| # | 级别 | 视觉规范条目 | 冲突说明 | 建议 |
|---|---|---|---|---|
| **1** | **必须改** | §7「30 COMBO：判定线上移到 y=536 并弹性回位（400ms）」 | 判定线在 400ms 内移动 24px，玩家的时空参照系被改变 → 判定随机感上升，直接摧毁"按得准"的爽感 | **取消**。改为判定线**亮度/纹理**变化（加一道同色描边 400ms），位置恒定 |
