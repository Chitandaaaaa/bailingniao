## 1. 美学方向（一句话定位）

> **「墨蓝天穹里的一张发光总谱」**——夜色的冷蓝是纸与天空，琥珀金的乐音是百灵鸟的羽光；
> 整张画面像一张被星光浸染的古老大总谱在缓慢卷动，音符是骑在谱线上坠落/升腾的符头。

**情绪关键词**：夜航 · 羽光 · 黄铜 · 克制的高光 · 纸墨质感 · 仪式感 · 爽脆
**明确排除**：赛博朋克紫粉渐变、霓虹网格、像素风、扁平 Material 卡片、彩虹糖果色

**为什么是深色底（强烈建议用深色，不要浅色）**
1. 发光是本游戏「爽感」的唯一载体。PERFECT 爆闪、粒子、屏震全靠加色混合（screen/additive），深底能把亮度推到 #FFF8E7 仍保留层次；浅底上任何发光都会被背景吃掉，HIGH 变 LOW。
2. 判定反馈的对比度预算：深底上「判定线 vs 背景」的 ΔL ≥ 0.45，判定窗口读得清；浅底上白线/白字直接糊。
3. 夜空的冷底 + 暖点（色温对比）比「白底 + 彩色」更能让音符成为唯一光源，也让 10/30/50/100 连击的庆祝有升级空间（浅底从第一秒就用满了）。
4. 唯一代价：文字与次要信息必须提亮到 #A9BCD2 以上，且避免大面积纯黑（用 #0D1A2C 蓝黑，保留纸墨感）。

### 2.4 音符与轨道色（5 轨区分色）

**规则：同形状不同色。** 形状是乐谱语义的载体（符头/符干/符尾），颜色是操作映射的载体。形状差异会逼玩家「辨认形状」而不是「跟着节奏走」，反而降低爽感。只有 3 种节奏型用形状区分（见 §5）。

| 轨道 | 键 | 名称 | HEX | HSL | L* | 备注 |
|---|---|---|---|---|---|---|
| 0 | ← | 琥珀金 | `#FFD166` | 43° 100% 70% | 79 | 最暖、亮度第二 |
| 1 | ↑ | 落日橙 | `#FF8A5C` | 19° 100% 68% | 65 | 与 MISS 玫红拉开 50°+ |
| 2 | 空格 | 象牙白 | `#F4F7FB` | 214° 33% 97% | 96 | **主角轨**，最亮、符干加长、落点垫最大 |
| 3 | ↓ | 薄荷绿 | `#63D9A6` | 155° 56% 62% | 78 | |
| 4 | → | 晴空蓝 | `#7FA8F0` | 220° 80% 71% | 67 | |

- 相邻轨道色相间隔 ≥ 36°，且亮度呈「2 最亮 → 0 → 3 → 4 → 1」阶梯，1× 缩放下也可辨。
- 中心轨道（空格）单独提亮到近白并加大落点垫（104×12），形成视觉主角 → 与「空格是主旋律键」一致。
- **禁止**：把 5 轨做成红黄绿蓝紫高饱和等差色环；禁止 5 轨同色仅靠亮度区分。

> ⚠️ **色板自身的已知缺陷（来自 interaction-spec §7.1）**：灰度近似下 轨道0 ≈ 186 / 轨道3 ≈ 180，轨道1 ≈ 146 / 轨道4 ≈ 152 —— **纯色标在灰度与红绿色盲下不可区分**。
> 因此轨道识别**不能只靠颜色**，本规范采用**四重冗余编码**（颜色只是其中一重，且是最后一重）：
>
> | 编码 | 实现 | 强度 |
> |---|---|---|
> | ① 位置 | 5 个固定 X（200/400/600/800/1000） | 最强 |
> | ② 序号 | 判定线下方每轨标 `1`–`5`（10px/700 tabular，text-lo alpha .40） | 强 |
> | ③ 唱名 | 判定线下方每轨标 `1 do` / `2 re` / `3 mi` / `4 fa` / `5 sol`（11px serif，text-lo alpha .80） | 中 |
> | ④ 落点垫尺寸 | 宽度 88/92/**104**/92/88、高 10/11/**12**/11/10 | 中（灰度下 10% 级差异） |
> | ⑤ 键位图例角标 | 左下 5 个键帽右上角标 `1`–`5`（11/700 tabular） | 辅助 |
>
> **色弱友好模式**（设置开关，默认关）：开启后 5 轨换用经色觉仿真校验的替代色板，要求 ① 相邻轨 ΔE ≥ 15（deuteranopia / protanopia 模拟）② 亮度形成单调阶梯 ③ 判定色不变；同时自动打开 GOOD 窗口虚线与落点垫预判高光。

### 3.3 排版规则（硬约束）

1. **字重只用 400 / 600 / 800 三档**，不出现 500/700，避免中文字重跳档导致的「脏」。
2. **所有会变动的数字（分数、连击、准确率、计数）必须 `font-variant-numeric: tabular-nums` + `font-feature-settings:"tnum" 1`**，否则数字宽度抖动，读数发飘。
3. 全大写标签统一 `ls 0.18em`；中文标题**不做**大写也不加字距（0.01em 即可），英文标签不做 `text-transform` 以外的装饰。
4. 数字与单位之间空 4px；`+120` 这类飘字用 tabular-nums 保证不跳。
5. 反馈文字（PERFECT/GOOD/MISS）必须有 2px 白色描边或 3px 深色投影，保证压在音符上仍可读。
6. 中文正文最大行宽 32 字符（约 420px），超长说明分两行居中。

## 4. 五线谱隐喻的具体落地

### 4.1 关键决策：把五线谱「竖置」

标准五线谱是 5 条**水平**线，但本作 5 轨是**垂直**的 x=200/400/600/800/1000。
**采纳方案：竖谱（把总谱旋转 90°）——5 条垂直轨道就是 5 根谱线，音符是骑在线上的符头。**
理由：一根垂直轨道同时是「五线谱的一根线」和「一条游戏轨道」，隐喻 100% 成立、零歧义，且笔记沿线下落 = 沿谱线「走」。

**同时保留水平层作为「纸面」**：背景极淡的水平细网格（y=120/260/400/540，opacity .10）暗示乐谱纸的横格，避免画面只有 5 根竖线显得单薄。
⚠️ 反例警告：水平线若画到 opacity > .18 会与轨道混淆，判定层立刻读不出来。

### 4.3 百灵鸟元素（3 处，克制使用）

1. **开始页主角**：一只侧飞百灵鸟剪影，SVG 路径，高 150px / 宽 260px，位于标题正上方 y=120~270。
   - 结构：身体（贝塞尔闭合轮廓）+ 3 根分层尾羽 + 一只上翘翅膀（独立 path，用 transform-origin 根部做 ±1.5° 摆动）。
   - 填色：`linearGradient` 琥珀 `#FFD98A → #FF8A5C`；描边 1px `#FFF4C8` opacity .7（描边是「光」，不是「线」）。
   - 动画：整体 translateY 0→-8px，6s ease-in-out alternate infinite；翅膀 1.8s 慢摆。
2. **游戏中掠影**：每 9s 一次，小鸟剪影沿抛物线从 (x=-140, y=520) 掠到 (x=1340, y=170)，高 34px，`#C7DCF2` opacity .22，带 6 段渐隐拖尾，1.6s 走完。存在感极低，只在余光提示「天空里有鸟」。
   - **层序说明**：该掠影画在 **L0 背景层（SVG）**，永远在 Canvas 音符层**之下**，不构成对音符的遮挡 → 不受 §12 保护区铁律约束。若实现时把它放到特效层，则必须移出保护区。
3. **羽毛粒子**：所有粒子不是圆点，而是**羽毛片**（见 §6）。这是百灵鸟母题最强的识别载体——哪怕玩家不认识鸟，羽毛也立刻把「普通下落方块」变成「有主题的游戏」。

❌ 不要：把音符本身做成鸟形。音符是符头，鸟是氛围与粒子。混用会让音符辨识度崩塌。

## 5. 音符造型

### 5.1 形状规范

**统一造型：符头 + 符干 + 高光（3 种节奏型变体）**

| 变体 | 形状 | 几何描述 |
|---|---|---|
| 标准 note | 符头（骑在谱线上，旋转 -20°） | 椭圆 rx=23 ry=15，中心对准谱线 x，整体上移 -2px 使线穿过符头腰线 |
| 长音 hold | 符头 + 竖直琴弦柱 | 同符头 + 从符头延伸到 y=560+120 的 6px 宽光带（轨道色 40% → 透明），判定线处有小方块锁扣 |
| 强音 accent | 符头 + 符干 + 符尾 | 符干从符头右上端向上 26px（3px 圆头竖线），顶端向左弯出一枚小旗（path `M0,0 C11,2 15,11 10,20 C9,12 5,8 0,8 Z`），flag 与符干同色但提亮 15% |

**符头 SVG path（推荐直接用，比椭圆更有手绘感）**
```
M -23,0 C -23,-11 -12,-18 2,-16 C 16,-14 23,-6 23,2 C 23,12 12,18 -2,16 C -16,14 -23,9 -23,0 Z
```
中心在 (0,0)，约 46×34，套 `transform="rotate(-20)"`。

### 5.2 材质与发光（三层叠加）

1. **主体渐变**：`linearGradient` 垂直 135°，轨道色 → 提亮 22% → 轨道色压暗 12%；中心 22% 宽度处放一条更亮的「高光条」。
2. **玻璃高光**：符头左上 1/3 处一枚椭圆 `rgba(255,255,255,.55)`，宽 14 高 7，旋转 -20°，opacity 随下落略降到 .35（模拟掠射角）。
3. **外发光**：符号外再复制一份同路径，`filter: blur(6px)` + 加色混合，opacity .55；强音音符 blur 提升到 10px。
4. **内阴影**：SVG `feComposite` 或 Canvas `shadow-inner` 模拟不可行时，用一条 1px 深色描边（轨道色压暗 30%，opacity .5）沿符头下半部替代——**保证符头在亮色爆闪时仍有轮廓**。

### 5.3 性能约束（关键）

**音符一律用 Canvas 绘制，且必须「预渲染 sprite」**：
- 离屏 canvas 缓存：5 轨道色 × 3 变体 = 15 张 PNG（每张 96×72，含发光）。
- 每帧只做 `drawImage`，绝不每帧 `createLinearGradient` / `shadowBlur`。
- ❌ 若用 SVG 逐音符挂 `feGaussianBlur` 滤镜，60 个音符就会掉帧，帧率一掉「爽感」直接归零。

## 6. 命中特效的分级视觉

三者**必须有可辨认的形状差异**，不能只换颜色（玩家要靠形状学会区分）；颜色是第三重编码（形状 → 文案 → 颜色）。

### 6.1 位置铁律：反馈文字放在**判定线下方**，不放判定线上方

**推导**（标准模式，noteSpeed 340 px/s，1/2 拍最小间隔 250ms）：

- 下一同轨音符在 t=0 时位于 `y = judgeY − 340×0.25 = judgeY − 85`。
- 它进入「判定线上方 56px 的文字带」的时刻 = `(56 − 85)/340 < 0` → **它已经穿过该带**，正在向判定线下落。
- 换算成「下一轨」：第 3 个同轨音符（T=0.5s）在 `t = 0.5 − 56/340 ≈ 0.335s` 重新进入该带，而判定文字此刻只剩 ~25ms 寿命。

⇒ **只要反馈文字画在轨道轴上、且位于判定线附近，就一定会被本轨音符穿过**（无论放线上还是线下 0~100px 区间）。
外扩偏移也救不了：PERFECT 文字宽约 92px，偏移 −46px 后仍覆盖本轨符头半宽 23px 的一部分。

**最终方案（5 轨同规则，含中心轨）**

| 项 | 值 |
|---|---|
| 判定文字基线 | `y = judgeY + 60`（PERFECT/GOOD/MISS 一致，仅字号不同） |
| 水平位置 | **居中于本轨中心 x**（200/400/600/800/1000），不外扩 —— 判定线正下方同轴 = 归属关系零歧义 |
| 归属引线 | 从 `judgeY + 6` 到 `judgeY + 40` 的 1px 竖线，轨道色 alpha .30，把判定线与文字连起来 |
| 所在区 | **判定线以下 = 音符永不经过**，保护区零占用 ✓ |
| 与唱名行 | 唱名基线 `judgeY + 26`（box 575–586），文字 box 598–620 → 净空 12px ✓ |
| 与 Combo 区 | Combo 标签基线 `judgeY + 90`（box 638–650）→ 净空 18px ✓ |

## 7. Combo 里程碑庆典（4 档，逐级加码）

### 7.1 位置铁律：里程碑一律落在**判定线以下的「里程碑带」**

- **下落通道保护区**：`x ∈ [172, 1028]` 且 `y ∈ [0, judgeY]`（5 轨符头 ±23px + 12px 余量）。
- 保护区内的**底板 / 文字块 / 图形块 / 持续 >200ms 的元素**一律禁止。
- 唯一例外：**L0 背景层（SVG）**中的元素永远在音符之下，不构成遮挡（如 §4.3 的掠影鸟）；例外不适用于 L1 谱面层与 L2 特效层。
- 允许：小尺寸（≤8px）、半透明（opacity ≤.60）、寿命 ≤500ms 的**粒子**，用于命中与庆祝的爆发感。

**几何铁律（v1.1）**：里程碑**不得改变判定线的位置、宽度、落点垫尺寸、判定窗口虚线位置**；只允许改颜色 / 亮度 / 光晕。判定线在整个 PLAYING 期间是恒定参照系。

## 9. SVG vs Canvas 分工

### 9.1 四层结构（推荐）

| 层 | 技术 | 内容 | 更新频率 |
|---|---|---|---|
| L0 背景 | CSS + SVG（静态） | 多层渐变、纸纹 `feTurbulence`、星尘、谱线、谱号、拍号、边界线、背景水平细网格、掠影鸟 | 仅在尺寸变化时重绘；呼吸/流动用 CSS animation。**永远在音符之下 → 不受保护区约束** |
| L1 谱面层 | **Canvas 2D** | 音符（sprite drawImage）、拖尾、落点垫、节拍线/小节线、判定线、PERFECT 窗口虚线、判定文字与引线、星芒 | 每帧。**受保护区约束** |
| L2 特效层 | **Canvas 2D**，`mix-blend-mode: screen` | 粒子（羽毛）、爆闪、涟漪、全屏白闪、里程碑光环、屏震时的色散光晕 | 每帧。**受保护区约束**；永远压在音符之上 |
| L3 HUD | **DOM + CSS**（少量 inline SVG 图标） | 分数、Combo、进度条、评级徽章、反馈文字、开始/暂停/结算三层覆盖层 | 事件驱动（DOM 文本节点更新） |

### 9.2 分工理由

**用 SVG 的部分**（矢量、可缩放、可加滤镜、低频更新、需要无障碍语义）
- 谱线、边界线、谱号、拍号、唱名、背景水平网格、纸纹滤镜、星尘、图标、键帽图例、结算徽章环、开始页百灵鸟剪影。
- 理由：`feGaussianBlur`/`feTurbulence` 在 SVG 里声明一次即可复用；路径放大不糊；`aria-label` 与 `role` 可直接挂；开始/暂停/结算本质是文档流布局，DOM 比 Canvas 画框更省事也更好做无障碍与焦点管理。

**用 Canvas 的部分**（每帧全量重绘、需要混合模式与粒子池）
- 音符、拖尾、爆闪、涟漪、粒子、里程碑光环、全屏闪白。
- 理由：数量 60~400 的元素逐帧重绘，DOM 会因重排/重绘管线卡死；Canvas 直接清屏 + 绘制，无布局成本。
- 混合模式：`screen` / `lighter` 在 Canvas 2D 上通过 `globalCompositeOperation` 即可实现，成本远低于 SVG `filter` 逐元素叠加。

### 9.3 性能预算（硬指标）

- 目标 60fps（120Hz 屏不低于 50fps），主线程单帧预算 ≤ 8ms。
- 音符 sprite 预渲染：5 色 × 3 变体 = 15 张离屏 PNG，只画一次。
- 粒子对象池上限 400，超出复用最旧；MISS 碎屑与羽毛分开计数。
- 每帧禁止：`createLinearGradient` / `shadowBlur` / DOM 读写交错（layout thrash）。
- 屏震期间不降粒子数——降粒子就等于降爽感。
- Canvas 按 `devicePixelRatio` 缩放（上限 2），CSS 尺寸固定 1200×800，外层用 `transform: scale()` 适配，逻辑坐标恒为 1200×800（前端只需一套坐标）。

## 10. 反例清单（出现即判为「不精致」）

**音符与谱面**
1. 纯色方块/圆点音符，无符头造型、无渐变、无高光 → 立刻变成网页 Demo。
2. 音符颜色与背景近似（如深蓝音符落在深蓝底）→ 漏接。
3. 5 轨做成红黄绿蓝紫的高饱和等差色环 → 儿童向、杂乱，中心轨道失去主角地位。
4. 用**水平**五线谱去对应**垂直**轨道，语义错位 → 隐喻不成立（除非刻意做成"背景网格"，且必须 opacity ≤ .18）。
5. 判定线只有 1px 实线、无落点垫、无辉光 → 发光特效无处附着，MISS 肉眼不可见。
6. 判定窗口（±30 / ±65）完全不可见 → 玩家判定凭感觉，随机感是「不精致」的头号来源。
7. 音符穿过判定线不消失或消失太晚 → 误判 + 视觉脏。
8. 音符在 y=-50 突然硬出现（无渐隐入场）→ 生硬；应 0→1 渐显入场。
9. 小节线/节拍线与音符不同速 → 时间感崩塌。

**反馈与特效**
10. 命中无反馈（按键没有任何光柱 / 轨道高亮）→ 玩家不知道输入是否被识别。
11. 每次命中都震屏 → 疲劳；震屏只给里程碑。
12. 粒子用 200 个圆形白光点 → 廉价烟花感，且丢掉羽毛这一主题识别点。
13. GOOD 与 MISS 仅靠颜色区分、没有形状/文字差异 → 玩家学不会。
14. 里程碑特效被音符盖住（层级错）→ 爽感失效。
15. 全屏渐变紫粉（赛博朋克模板）→ 与百灵鸟/乐谱主题无关。

**排版与质感**
16. 默认系统字体做 HUD 分数（Times / 宋体 / Arial）→ 游戏感归零。
17. 变动数字未用 tabular-nums → 读数抖动。
18. 灰底（#333 / #f0f0f0）+ 白/纯黑线 → 无夜戏感，且发光全废。
19. 背景纯黑 `#000` → 纸墨质感丢失，五线谱隐喻断裂；应至少用带蓝相的 `#0D1A2C`。
20. 面板用浏览器默认 `alert`/`confirm`、或原生 `select` 做设置 → 廉价。
21. 覆盖层用系统默认按钮样式 → 与游戏内 UI 不成套。
22. 音符用 SVG 逐个挂 `feGaussianBlur` 滤镜 → 掉帧直接毁掉一切。
23. 小字用 `#6C819B` 以下灰度做关键信息 → 不可读。
24. 唱名/拍号/谱号用无衬线体 → 失去「乐谱」这一层说服力（这三处必须 serif）。

**遮挡与参照系（v1.1 新增，来自 interaction-spec §4 / §11）**
25. 反馈文字画在**轨道轴上**且贴近判定线 → 必然被本轨下一个音符穿过（推导见 §6.1）。正确做法：判定文字放判定线**下方** `judgeY+60`，同轴居中。
26. 里程碑横幅 / 徽章 / 鸟剪影横跨下落通道（x∈[172,1028], y<judgeY）→ 直接遮住要打的音符。
27. 判定线在游戏中位移、变宽、变双线 → 玩家的时空参照系被改动，判定随机感上升。
28. 落点垫按下时改变尺寸 → 玩家会误判 PERFECT 窗口边界；按下只允许改亮度/光晕。
29. 把 MISS 玫红 `#FF4D6D` 挪用到 Combo 数字、菜单按钮等非判定元素 → 「红色 = 失误」语义串味。
30. 只用颜色区分 5 轨（灰度下 0/3 与 1/4 亮度接近）→ 色觉差异玩家无法识别轨道；必须叠加序号 / 唱名 / 键位图例 / 落点垫尺寸四重冗余。
31. 判定线以下的坐标硬编码 560 → 移动端 judgeY=620 时整体错位；必须相对 judgeY 推导。

## 12. 视觉不变量与保护区铁律（v1.1 新增，优先于本文档其它描述）

| # | 铁律 | 理由 |
|---|---|---|
| I1 | **判定线几何恒定**：PLAYING 期间判定线的位置、线宽、落点垫尺寸与位置、判定窗口虚线位置一律不变；只允许改颜色 / 亮度 / 光晕 | 参照系一旦移动，「按得准」的爽感变成「判定随机」 |
| I2 | **下落通道保护区**：`x ∈ [172,1028]` 且 `y ∈ [0, judgeY]` 内，禁止出现底板 / 文字块 / 图形块 / 持续 >200ms 的元素 | 特效不能挡住下一个音符 |
| I3 | **保护区例外**：L0 背景层（SVG）元素永远在音符之下，不构成遮挡；小尺寸（≤8px）、opacity ≤.60、寿命 ≤500ms 的粒子允许穿过通道 | 保留爆发感与背景叙事 |
| I4 | **判定反馈独占**：同一轨道同时只允许 1 个反馈实例；新判定把旧的 60ms 淡出移除 | 密集打同轨时不叠成一团 |
| I5 | **判定色专用**：`#FFF4C8` / `#4FD1E8` / `#FF4D6D` 只用于判定反馈，不得用于 Combo、里程碑、HUD、菜单按钮 | 保住「颜色 = 判定结果」的语义 |
| I6 | **判定文字位置**：基线 `judgeY+60`，水平居中于本轨 x，5 轨同规则（含中心轨）；归属靠 1px 竖引线（judgeY+6→+40） | 见 §6.1 推导；外扩偏移同样会被本轨音符压到 |
| I7 | **反馈寿命**：判定文字 ≤360ms，且必须 ≤ 相邻两音符最小间隔 × 0.7 | 防止与下一音同帧 |
| I8 | **里程碑带**：所有里程碑文字 / 徽章落在 `judgeY+100 ~ judgeY+156`（桌面 660–716），互斥切换 | 保护区零占用 + 构图统一 |
| I9 | **坐标可推导**：`judgeY` / `spawnY` / `noteSpeed` / `beatGap` 全部是变量；所有判定线以下坐标相对 judgeY 推导 | 移动端 judgeY=620 / 练习模式 290px/s 需即时生效 |
| I10 | **非颜色冗余**：轨道识别必须有位置 / 序号 / 唱名 / 键位图例 / 落点垫尺寸 中的至少三重 | 灰度与色盲下颜色不可靠 |
| I11 | **层级**：特效永远压在音符之上（fx canvas，screen 混合）；背景永远在音符之下 | 既不遮音符也不被遮 |
| I12 | **减弱动效**：`prefers-reduced-motion` 下屏震 A0=0、白闪改内发光、粒子数 ×0.35（数值以 interaction-spec §7.3 为准） | 前庭敏感 |
